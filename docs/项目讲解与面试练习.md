# 项目讲解与面试练习

这个项目是离线检索实验，不是完整的 RAG 系统。先亲手运行并检查输出，再根据实际参与情况描述；AI 辅助编写或运行的工作不冒充本人独立完成。

## 讲解顺序

1. 问题：在公开数据集上比较关键词检索、向量检索和两路融合的排序质量。
2. 流程：数据加载 → BM25 和句向量/HNSW 检索 → RRF 融合 → 根据标注计算质量指标。
3. 结果：在当前 SciFact 实验中融合 nDCG@10 为 0.6853，BM25 为 0.6645；解释它们只是本数据及配置下的测量。
4. 案例：查询 784 中相关文档排名 3/2/1；查询 1088 中稠密排名第 1 而融合掉出前 10。
5. 边界：语料小、历史缓存尚未从头复核、耗时不包括查询编码；重排代码尚无真实模型实验。

## 高频问题

- BM25 如何使用词频、逆文档频率、文档长度？语义相近但词不同会怎样？
- 向量为什么归一化？HNSW 是精确检索吗？M 与 efSearch 影响什么？
- RRF 为什么按名次融合？k 变大或变小对头部权重有什么影响？
- Recall@100 与 nDCG@10 的分母和含义分别是什么？未标注文档是否一定不相关？
- 为什么融合可能变差？结合查询 1088 回答，而不是声称融合一定提升。
- 为什么结果不能证明工业级性能？计时包括和排除了哪些部分？
- 重排能否召回候选之外的文档？如果只重新排序全部 100 个候选，Recall@100 为什么不变？
- 你实际完成了什么？哪些代码由工具辅助？如何亲手运行、验证和修改？
